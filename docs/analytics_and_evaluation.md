# Analytics & Evaluation

This document explains how to read and analyze the simulation output data generated by SUMO, and how to conduct a rigorous comparison between the adaptive Time Extension controller and a conventional fixed-time baseline.

---

## 1. Output Files

Each simulation run generates three XML files in the `output/` directory:

| File | SUMO Attribute | Description |
| :--- | :--- | :--- |
| `output/summary.xml` | `--summary-output` | Per-step aggregate statistics (running vehicles, halting count, mean speed, emissions) |
| `output/tripinfo.xml` | `--tripinfo-output` | Per-vehicle trip statistics (departure time, arrival time, waiting time, route length) |
| `output/queue.xml` | `--queue-output` | Per-step queue length per approach lane |

---

## 2. Key Performance Indicators (KPIs)

### From `tripinfo.xml`

Parse using Python's `xml.etree.ElementTree`:

```python
import xml.etree.ElementTree as ET
import statistics

tree = ET.parse("output/tripinfo.xml")
root = tree.getroot()

wait_times    = [float(v.get("waitingTime", 0)) for v in root.iter("tripinfo")]
travel_times  = [float(v.get("duration", 0))    for v in root.iter("tripinfo")]
route_lengths = [float(v.get("routeLength", 0)) for v in root.iter("tripinfo")]

print(f"Average Waiting Time : {statistics.mean(wait_times):.2f}s")
print(f"Average Travel Time  : {statistics.mean(travel_times):.2f}s")
print(f"Total Vehicles       : {len(wait_times)}")
```

| Metric | Attribute | Lower is Better |
| :--- | :--- | :--- |
| Average Waiting Time | `waitingTime` | ✅ |
| Average Travel Time | `duration` | ✅ |
| Average Route Length | `routeLength` | — (informational) |

### From `summary.xml`

```python
tree = ET.parse("output/summary.xml")
root = tree.getroot()

for step in root.iter("step"):
    time      = step.get("time")
    halting   = step.get("halting")      # Number of stopped vehicles
    mean_speed = step.get("meanSpeed")   # Mean speed across network (m/s)
    print(f"t={time}s | Halting={halting} | MeanSpeed={mean_speed} m/s")
```

## 3. Emissions & Environmental Impact

SUMO automatically computes per-vehicle emissions using the **HBEFA3/PC_G_EU4** emission model. Emission data is embedded in `tripinfo.xml`:

| Attribute | Pollutant / Resource |
| :--- | :--- |
| `CO2_abs` | Carbon dioxide (g) |
| `CO_abs` | Carbon monoxide (g) |
| `HC_abs` | Hydrocarbons (g) |
| `NOx_abs` | Nitrogen oxides (g) |
| `PMx_abs` | Particulate matter (g) |
| `fuel_abs` | Fuel consumption (ml) |
| `electricity_abs` | Energy (if electric vehicle) |

```python
co2_total  = sum(float(v.get("CO2_abs",  0)) for v in root.iter("tripinfo"))
fuel_total = sum(float(v.get("fuel_abs", 0)) for v in root.iter("tripinfo"))
print(f"Total CO2 emitted  : {co2_total:.1f}g")
print(f"Total fuel burned  : {fuel_total:.1f}ml")
```

## 4. Comparative Evaluation: Adaptive vs Fixed-Time

### Step 1 — Run Fixed-Time Baseline

Disable the adaptive controller by commenting out `controller.step()` in `main.py`. SUMO will use the base fixed-time signal program generated by `netconvert` (35s green / 4s yellow by default).

```python
# controller.step(step_length=0.1)  # Disabled for baseline run
```

Run the simulation with identical parameters (same `RANDOM_SEED`, same TLS layout, same orderliness level) and save the `output/` files as `output_fixed/`.

### Step 2 — Run Adaptive Controller

Re-enable `controller.step()` and run again. Save results as `output_adaptive/`.

### Step 3 — Compare Results

| KPI | Fixed-Time | Adaptive | Improvement |
| :--- | :--- | :--- | :--- |
| Avg. Waiting Time (s) | `?` | `?` | `Δ%` |
| Avg. Travel Time (s) | `?` | `?` | `Δ%` |
| Total CO2 (g) | `?` | `?` | `Δ%` |
| Total Fuel (ml) | `?` | `?` | `Δ%` |

Improvement formula:

```
Improvement (%) = ((Fixed - Adaptive) / Fixed) × 100
```

A positive value means the adaptive controller outperforms the fixed-time baseline.

## 5. Queue Growth Analysis

From `queue.xml`, plot queue length over time per direction to visually identify:
- **Congestion spikes** — periods where queue builds faster than the green phase can clear.
- **Phase Skipping effectiveness** — empty-direction skips should correlate with sudden drops in other directions' queue length.
- **Max-Out occurrences** — forced green terminations should appear as queue plateau moments followed by rapid queue growth on the opposing axis.
